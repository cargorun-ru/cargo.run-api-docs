# Order Lifecycle API

Раздел описывает методы управления жизненным циклом заказа.

---

## 1. Запуск заказа в работу

```http
POST /api/Orders/StartOrder?Id={order_id}
```

Запускает заказ из черновика или подготовленного состояния.

После запуска заказ становится доступен перевозчикам в соответствии с настройками видимости.

---

## 2. Отмена заказа

```http
POST /api/Orders/CancelOrder
```

### Тело запроса

```json
{
  "id": 798805,
  "saveInDirectory": false,
  "fromBook": false,
  "cancellationReasonComment": "машина сломалась"
}
```

Если причина выбирается из справочника:

```json
{
  "id": 798805,
  "saveInDirectory": false,
  "fromBook": true,
  "cancellationReasonIds": [5, 6]
}
```

### Справочник причин отмены

```http
GET /api/CancellationReasons/SelectByOrderList?OrderId={order_id}
```

Метод поддерживает фильтрацию и пагинацию.

---

## 3. Возврат в черновик

```http
POST /api/Orders/OrderToDraft?Id={order_id}
```

Возвращает отмененный заказ в статус черновика.

При возврате очищаются данные, присвоенные в ходе выполнения заказа, например выбранный перевозчик и фактические времена по точкам.

---

## 4. Удаление заказа

```http
POST /api/Orders/Delete
```

### Тело запроса

```json
{
  "id": 798805
}
```

Удаление заказа является необратимым. Удаленный заказ не отражается в отчетах.
