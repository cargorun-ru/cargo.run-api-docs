# Надёжность интеграции

## Рекомендуемая схема

```text
Первоначальная загрузка  → ReadQuery
Оперативные изменения   → entity.changed
Полные данные           → Read / Bid / Default
Фактический маршрут     → Bids/GetActualRoute
Контрольная сверка      → периодический ReadQuery
```

Webhook ускоряет доставку, но не является единственным источником восстановления.

## Курсор списка

Используйте сортировку:

```text
$orderby=updatedAt,id
```

Сохраняйте пару `(updatedAt, id)` последней успешно обработанной заявки. Следующий запрос выполняйте с небольшим перекрытием по времени и удаляйте дубли по `id`.

Если `ReadQuery` не содержит фильтр по `updatedAt`, сервер ограничивает выборку заявками, изменёнными за последние 30 дней.

## Идемпотентность создания

Для синхронного [`Bids/Apply`](reference/endpoints.md#post-apiintegrationsbidsapply) повторяйте запрос с тем же `externalId`.

Для асинхронной очереди дополнительно используйте уникальный `Idempotency-Key`. Повтор с тем же ключом в течение 24 часов возвращает существующую задачу.

## Повторные запросы

| Ситуация | Поведение |
|---|---|
| Сетевая ошибка или timeout | Повтор с увеличивающейся задержкой |
| `401` | Один раз обновить токен и повторить |
| `400` | Не повторять без исправления данных |
| `403` | Не повторять без изменения доступа |
| `429` | Уважать `Retry-After`, снизить частоту |
| `5xx` | Ограниченный повтор с jitter и exponential backoff |

## Защита от устаревших событий

- дедуплицируйте webhook по `eventId`;
- сравнивайте `updatedAt` заявки;
- не рассчитывайте на порядок доставки;
- считайте webhook сигналом перечитать объект, а не полным журналом переходов;
- храните обработку события и изменение локальных данных атомарно либо используйте собственную очередь.

## Удаление и прекращение доступа

При удалении или прекращении трансляции CARGO.RUN отправляет изменение прежней аудитории. Последующий `Read` может вернуть объектную ошибку о недоступности. Поле `isDeleted=true` в краткой модели означает, что партнёр должен прекратить отслеживание заявки.

## Совместимость

Клиент должен:

- игнорировать неизвестные JSON-поля;
- не завершать весь процесс из-за неизвестного enum;
- сохранять исходное неизвестное значение для диагностики;
- не полагаться на порядок полей JSON;
- учитывать, что в ответы могут добавляться новые необязательные поля.
