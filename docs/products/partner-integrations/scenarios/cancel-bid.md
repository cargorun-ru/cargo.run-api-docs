# Отмена заявки

Для передачи отмены из партнёрской платформы в CARGO.RUN используйте синхронный
метод:

```http
POST <baseUrl>/api/integrations/Bids/Cancel
Authorization: Bearer <accessToken.token>
Content-Type: application/json
```

Метод отменяет доступную текущему партнёру заявку независимо от её источника: это
может быть заявка, созданная самим партнёром, либо заявка перевозчика,
транслируемая его платформе.

## Отмена по ID CARGO.RUN

Это предпочтительный способ. Используйте `id`, сохранённый после создания или
получения заявки:

```json
{
  "id": 12345
}
```

Если `id` передан, `externalPlatformOrderId` и `inn` игнорируются.

## Отмена по идентификатору заказа платформы

Если внутренний ID неизвестен, передайте строковый идентификатор заказа и ИНН
организации перевозчика:

```json
{
  "externalPlatformOrderId": "2471970",
  "inn": "7701234567"
}
```

Для такого поиска у интеграционного клиента должна быть настроена платформа.
Заявка определяется по сочетанию организации, платформы и
`externalPlatformOrderId`. Значение идентификатора не должно превышать 72 символа,
ИНН должен состоять из 10 или 12 цифр.

## Результат и ограничения

При успехе сервер возвращает `200 OK` с пустым телом. Статус заявки меняется на
`Canceled`; при следующем чтении событий появляется `BidCanceled`. Стандартные
уведомления CARGO.RUN об отмене отправляются согласно настройкам заявки и
получателей.

Метод не принимает причину отмены. Заявки в статусах `Done` и `Canceled` отменить
нельзя; повторная отмена также завершается бизнес-ошибкой `400`. Если заявка не
найдена или недоступна текущему партнёру, сервер не раскрывает причину и возвращает
ошибку о недоступной заявке.

Отмена реализована только синхронно. Команды `Cancel` или `Delete` для заявки в
`POST /api/integrations/Tasks/Queue` нет.
