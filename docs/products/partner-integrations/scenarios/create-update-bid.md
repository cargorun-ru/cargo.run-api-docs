# Создание и обновление заявки

Партнёр может создать или полностью обновить заявку синхронно либо через очередь. В обоих вариантах используется одна модель `ApplyBidFromIntegrationContext`.

## Предварительные условия

- организация существует;
- организация создана партнёрским сервисом или текущему партнёру явно выдан доступ;
- [`Organizations/Check`](../reference/endpoints.md#get-apiintegrationsorganizationscheck) возвращает `canCreateBids=true`;
- для создания переданы водитель, автомобиль, груз и минимум две точки;
- среди точек есть хотя бы одна погрузка и одна выгрузка.

Организация задаётся обязательным полем `inn`: 10 цифр для юридического лица или 12 цифр для ИП. Это правило одинаково для синхронного и асинхронного вариантов.

## Синхронный вариант

```http
POST <baseUrl>/api/integrations/Bids/Apply
Authorization: Bearer <accessToken.token>
Content-Type: application/json
```

```json
{
  "inn": "7701234567",
  "bid": {
    "externalId": "ORDER-2471970",
    "externalPlatformOrderId": "2471970",
    "comment": "Доставка груза",
    "counterparty": {
      "name": "ООО Ромашка",
      "inn": "7701234567"
    },
    "vehicleType": {
      "name": "Рефрижератор",
      "tonnage": 20,
      "volume": 82
    },
    "temperatureRegime": {
      "minimum": 2,
      "maximum": 6
    },
    "cargos": [
      {
        "name": "Паллетированный груз"
      }
    ],
    "bidPoints": [
      {
        "externalId": "POINT-LOAD-1",
        "type": "LoadPoint",
        "client": "ООО Грузоотправитель",
        "planEnterDate": "2026-10-08T10:00:00",
        "geozone": {
          "location": {
            "coordinates": [37.6176, 55.7558]
          },
          "address": "Москва, улица Примерная, 1"
        }
      },
      {
        "externalId": "POINT-UNLOAD-1",
        "type": "UnloadPoint",
        "client": "ООО Грузополучатель",
        "planEnterDate": "2026-10-09T10:00:00",
        "geozone": {
          "address": "Казань, улица Примерная, 2"
        }
      }
    ],
    "car": {
      "number": "А123АА777",
      "brandName": "КАМАЗ"
    },
    "driver": {
      "fullName": "Иванов Иван Иванович",
      "phoneNumber": "+79991234567"
    }
  }
}
```

Успешный ответ:

```json
{
  "id": 12345,
  "isRouteBuilt": true
}
```

Заявка автоматически запускается в работу. Если найденная заявка ещё не запущена, обновление также запускает её.

`bid.externalId` — строковый идентификатор заявки в системе партнёра. Поле
`bid.externalPlatformOrderId` — строковый идентификатор заказа на платформе
текущего интеграционного клиента. Если он передан и у клиента настроена платформа,
CARGO.RUN связывает с ней заявку и возвращает значение в `GetList`. Числовой
идентификатор также передавайте строкой, например `"2471970"`.

`bidPoints[].externalId` — строковый идентификатор точки в системе партнёра.
Числовые идентификаторы также передавайте строкой, например `"12345"`. При
обновлении CARGO.RUN использует это поле для сопоставления существующих точек.

Водителя можно передать одним полем `driver.fullName`. CARGO.RUN разделит значение
на фамилию, имя и отчество. Поддерживаются две или три части, порядок
«Фамилия Имя Отчество», порядок «Имя Отчество Фамилия» и инициалы. Если заполнено
`fullName`, отдельные `firstName`, `lastName` и `patronymic` не учитываются. Это же
правило действует для `secondaryDriver`.

!!! warning "Одна активная заявка на машину"
    Если у организации не подключён модуль планирования, запуск заявки может
    завершиться ошибкой `Уже имеется начатая заявка с данной машиной.` при наличии
    другой активной заявки на тот же автомобиль. Проверка не ограничивается
    пересечением плановых дат и не использует сочетание «машина + водитель».

    В режиме учёта пробега по прицепу проверяется прицеп. При подключённом модуле
    планирования вместо этого применяется настроенный лимит запланированных заявок.

После завершения ID заявки находится в `objects[].id`. `isRouteBuilt` через очередь не возвращается.

## Создание связанных сущностей

- водитель ищется в организации по `phoneNumber`; при отсутствии создаётся;
- `fullName` используется при создании нового водителя; у найденного по телефону
  водителя существующее ФИО не изменяется;
- автомобиль ищется по `number`; при отсутствии создаётся;
- прицеп необязателен; если он передан, `trailer.number` обязателен, а отсутствующий прицеп создаётся;
- первый и второй водитель обрабатываются независимо.

### Контрагент перевозки

`counterparty` необязателен. Если он передан:

1. `name` обязателен и не должен превышать 256 символов;
2. `inn` обязателен и должен состоять ровно из 10 или 12 цифр;
3. контрагент ищется в организации по ИНН;
4. если совпадение не найдено, создаётся новый контрагент;
5. найденный или созданный контрагент становится заказчиком заявки.

ИНН должен состоять из 10 или 12 цифр. При совпадении по ИНН уже существующий
контрагент используется без переименования.

### Грузоотправитель и грузополучатель

`bidPoints[].client` относится к конкретной точке и не заменяет `bid.counterparty`:

- в `LoadPoint` укажите грузоотправителя;
- в `UnloadPoint` укажите грузополучателя.

Поле имеет тип `string`. Оно сохраняется в точке и доступно в детальной карточке,
но не возвращается в сокращённом `GetList.points`. Для `LoadUnloadPoint` существует
только одно поле `client`; передать разных грузоотправителя и грузополучателя в
одной совмещённой точке действующий контракт не позволяет.

### Тип и вместимость ТС

`vehicleType` необязателен, но переданный объект должен содержать хотя бы одно из
полей `name`, `tonnage`, `volume`. Тип и характеристики записываются в прицеп, если
он есть в заявке, иначе — в автомобиль.

- `name` — не более 128 символов;
- `tonnage` и `volume`, если переданы, должны быть больше нуля;
- тип создаётся в отдельном справочнике организации без дублей;
- при тоннаже название имеет вид `Рефрижератор, 20 т`;
- если тоннажа нет, но есть объём — `Рефрижератор, 82 м3`;
- если переданы тоннаж и объём, в название входит тоннаж, но обе характеристики
  записываются в ТС;
- если `name` отсутствует, переданные тоннаж или объём обновляют характеристики,
  не изменяя существующий тип ТС.

Это изменение данных справочника автомобиля или прицепа, а не только снимка заявки.

### Температурный режим

`temperatureRegime` необязателен. Если объект передан, обязательны обе границы:

- `minimum` и `maximum` находятся в диапазоне от −30 до 30 °C включительно;
- `minimum` строго меньше `maximum`.

Для новой организации, создаваемой партнёрским сервисом, модуль «Температурный
режим» включается сразу. Для ранее созданной таким способом организации он
включается при первой заявке с `temperatureRegime`.

## Требования к маршруту

- минимум две точки;
- `type` обязателен для каждой точки; разрешены `LoadPoint`, `UnloadPoint` и
  `LoadUnloadPoint`;
- среди точек должна быть хотя бы одна отдельная `LoadPoint` и одна отдельная
  `UnloadPoint`; совмещённая `LoadUnloadPoint` сама по себе это условие не выполняет;
- `planEnterDate` обязательно для каждой точки;
- порядок маршрута определяется `planEnterDate`: CARGO.RUN сравнивает даты после приведения к UTC и сортирует точки по возрастанию; поле `order` во входной модели не передаётся;
- время передаётся как локальное время точки без UTC-смещения;
- `geozone.address` — обязательная непустая строка;
- `geozone.location` необязателен: без координат CARGO.RUN геокодирует точку по адресу;
- переданные части адреса сохраняются, а отсутствующие заполняются результатом геокодера;
- если координаты переданы, они имеют формат `[долгота, широта]`;
- часовой пояс определяется CARGO.RUN по итоговым координатам.

`bidPoints[].externalId` имеет тип `string`. Если идентификатор точки в системе
партнёра числовой, передавайте его строкой, например `"12345"`. Отдельного поля
типа `int64` для внешнего идентификатора точки нет.

Долгота должна находиться в диапазоне от −180 до 180, широта — от −90 до 90. Пара координат `[0, 0]` не принимается.

## Груз, стоимость и НДС

- передайте как минимум один элемент `cargos[]`;
- у каждого груза обязательно поле `name`;
- если `price` не передана, CARGO.RUN создаёт заявку на порожний пробег;
- если `price` передана, поле `vat` обязательно;
- `vat` передаётся строкой со значением `0`, `10`, `20` или `22`.

В основном сценарии используются погрузка (`type="LoadPoint"`) и выгрузка
(`type="UnloadPoint"`). Для совмещённой операции используйте
`type="LoadUnloadPoint"`.

## Обновление

После создания сохраняйте внутренний `bid.id`, полученный от CARGO.RUN, и
используйте его для дальнейшей работы с заявкой. `externalId` не гарантируется
уникальным и не должен быть единственным локальным ключом.

Текущая реализация `Apply` также выполняет поиск по переданному `externalId` внутри
организации, найденной по `inn`:

- если заявка найдена, её внутренний `id` имеет приоритет над переданным `bid.id`;
- если заявка по `externalId` не найдена, для обновления используется переданный `bid.id`;
- если не найдена заявка по `externalId` и `bid.id` не указан, создаётся новая заявка.

Если значения `externalId` повторяются, результат такого поиска неоднозначен.
Поэтому не полагайтесь на него при обновлении: передавайте сохранённый `bid.id` и
не переиспользуйте `externalId` без необходимости.

Частичное обновление не поддерживается. Передавайте полную актуальную модель.

При повторном `Apply` CARGO.RUN старается сохранить существующие точки, их `id`,
статусы прохождения и фактические отметки:

1. точки с `externalId` сопоставляются по этому идентификатору;
2. точки без `externalId` — по порядковому номеру после сортировки и `type`;
3. несопоставленная точка создаётся заново.

Передавайте стабильный и уникальный внутри заявки `bidPoints[].externalId`. Если
полагаться на порядок, изменение дат или состава маршрута может привести к
сопоставлению с другой точкой.
