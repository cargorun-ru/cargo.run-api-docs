# Для LLM и ИИ-агентов

Документация доступна в двух машиночитаемых представлениях.

## Индекс документации

[Открыть `llms.txt`](../../llms.txt)

Краткий индекс содержит ссылки на разделы документации и поясняет назначение каждого раздела. Используйте его, если ИИ-агент может самостоятельно открывать ссылки и загружать необходимые материалы.

## Полная документация

[Открыть `llms-full.txt`](../../llms-full.txt)

Файл содержит весь раздел интеграции с партнёрскими сервисами в одном документе. Используйте его для систем без доступа к сайту, подготовки базы знаний или передачи полного контекста модели.

## Рекомендации

- Начинайте с `llms.txt`, чтобы не загружать лишний контекст.
- Используйте `llms-full.txt`, если агенту требуется анализ всей интеграции или проверка связей между сценариями, методами и моделями.
- Считайте опубликованную документацию источником требований к интеграции. Секреты, токены и реальные персональные данные в контекст модели не передавайте.

## Правила для агентов

- Сначала проверьте аудиторию: этот API предназначен для операторов партнёрских
  платформ. Для собственной системы организации или 1С используйте документацию
  CARGO.RUN Логистика.
- Не вызывайте удалённый `Bids/GetCurrentList`; используйте объединённый `Bids/GetList`.
- Определяйте источник записи по `isCreatedByPlatform`, а не по наличию `externalId`.
- Перед вызовом `GetList` явно решите, нужна одна организация или все доступные:
  отсутствие `X-Organization-Id` расширяет область выборки.
- Для чтения и обновления сохраняйте `id` CARGO.RUN: `externalId` не уникален.
- Для транслируемой заявки сопоставляйте заказ партнёра по числовому
  `externalPlatformOrderId`, а не по `externalId`.
- `Bids/Apply` принимает `bid.externalPlatformOrderId`; если поле передано и у
  клиента настроена платформа, значение возвращается в `GetList`.
- Считайте `bidPoints[].externalId` и `points[].externalId` строкой, даже если
  идентификатор состоит только из цифр.
- `driver.fullName` заменяет отдельные части ФИО; при его наличии `firstName`,
  `lastName` и `patronymic` не учитываются.
- ETA ближайшей непосещённой точки находится в `estimatedBidPointId`,
  `estimatedEnterDate` и `estimatedDuration` на уровне заявки `GetList`.
- В списочной модели `updatedAt` учитывает изменения ETA; используйте его как курсор
  `GetList` и `ReadQuery`, но не приравнивайте к `updatedAt` детальной модели.
- Во входных точках передавайте обязательный `type`: `LoadPoint`, `UnloadPoint` или
  `LoadUnloadPoint`. Отдельные `LoadPoint` и `UnloadPoint` всё равно обязательны.
- Если передан `counterparty`, передавайте и `name`, и `inn`.
- При синхронном чтении проверяйте тело ответа: недоступная заявка обычно даёт
  `200 OK` с пустым телом.
- Передавайте непустой адрес каждой точки. Координаты можно опустить, но ошибка
  геокодирования требует исправления адреса, а не слепого повтора.
